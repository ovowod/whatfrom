## Agent Brief

**Category:** enhancement
**Summary:** 최상위 모듈의 import 규칙을 계층 테스트로 강제한다.

**Current behavior:**
계층 테스트는 stage package와 `core`만 검사한다. 최상위 모듈 가운데 stage를 조합하는 것은 `api`와 `cli`다. 나머지 최상위 모듈(지금은 `metrics`, `admission`)은 `core`만 import하거나 whatfrom 모듈을 하나도 import하지 않는다. 하지만 이 규칙을 강제하는 테스트가 없다.

**Desired behavior:**
규칙은 다음과 같다. "`whatfrom` 최상위 모듈 가운데 `api`와 `cli`만 stage를 조합할 수 있다. 그 밖의 최상위 모듈은 `whatfrom.core`만 import할 수 있다." 기존 계층 테스트 파일이 이 규칙을 같은 방식(ast 파싱)으로 검사한다. 금지 대상은 stage만이 아니다. `whatfrom.core`가 아닌 내부 module은 모두 금지하며, `api`, `cli`, 다른 최상위 module도 여기에 들어간다. 내부 import를 찾는 parser는 `from whatfrom import search` 같은 형태도 실제 module 이름으로 해석해야 한다. 이 parser 수정은 기존 stage·core 계층 테스트에도 그대로 적용된다. 앞으로 최상위 모듈이 새로 생기면 자동으로 검사 대상이 된다. 테스트 모듈의 docstring에도 이 규칙을 추가한다.

**Acceptance criteria:**
- [ ] `api`, `cli`, `__init__`, `__main__`(있다면)을 제외한 최상위 `.py` 모듈이 `whatfrom.core` 외의 내부 module(stage, `api`, `cli`, 다른 최상위 module)을 import하면 실패하는 테스트가 있다.
- [ ] `from whatfrom import <module>` 형태도 검출한다. 작은 source fixture로 parser를 검증하는 테스트가 있다.
- [ ] 현재 코드에서 통과한다.
- [ ] 위반 메시지가 기존 테스트처럼 파일과 줄 번호를 알려 준다.

**Out of scope:**
- 최상위 모듈의 위치 이동.
- `api`나 `cli`의 import 정리.

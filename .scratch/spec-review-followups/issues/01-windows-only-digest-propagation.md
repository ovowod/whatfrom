# Windows 전용 태그와 같은 digest를 가리키는 태그가 후보에 남는다

Status: ready-for-agent
Category: bug
Source: Spec 리뷰 — `docs/superpowers/specs/2026-09-17-release-line-candidates-design.md` §3.1

## 문제

spec §3.1은 이렇게 요구한다.

> 다음 태그를 빼고, 이들과 같은 digest를 가리키는 태그도 함께 뺀다

제외 대상에는 Windows 전용 태그도 들어 있다. 그런데 `select_tags`는 Windows 전용 태그를 이름으로만 거른다. digest를 따라 함께 빼는 처리는 `_exclude_prerelease`에서만 하므로, 프리릴리스와 날짜 스냅샷에만 적용된다.

## 위치

- `src/whatfrom/search/tagselect.py:75`: `linux = [ref for ref in tags if not WINDOWS_ONLY.search(ref.tag)]`
- `src/whatfrom/search/tagselect.py:126-146`: `_exclude_prerelease`. digest 전파가 여기에만 있다.
- `stale_pinned_lines`(`tagselect.py:106`)도 같은 방식으로 거른다.

## 완료 조건

- 이름에 Windows 표시가 없지만 Windows 전용 태그와 digest가 같은 태그가 후보에서 빠진다. 이를 검증하는 테스트를 추가한다.
- digest가 None인 태그는 전파의 근거로 쓰지 않는다. 기존 규칙과 같다.

## Agent Brief

**Category:** bug
**Summary:** 후보 태그 선택에서 Windows 전용 태그와 같은 digest를 가리키는 태그도 함께 뺀다.

**Current behavior:**
`select_tags`는 Windows 전용 태그를 이름(`WINDOWS_ONLY` 정규식)으로만 거른다. 이름에 Windows 표시가 없는 태그는 Windows 전용 태그와 같은 manifest digest를 가리켜도 후보에 남는다. digest를 따라 함께 빼는 처리는 프리릴리스와 날짜 스냅샷에만 적용된다.

**Desired behavior:**
release-line-candidates spec §3.1대로 처리한다. Windows 전용 태그를 빼고, 그 태그와 `manifest_digest`가 같은 태그도 함께 뺀다. 프리릴리스와 같은 규칙을 따른다. 즉 digest가 None인 태그는 전파의 근거로도, 대상으로도 쓰지 않는다. 같은 제외 규칙을 쓰는 `stale_pinned_lines`도 같은 결과를 내야 한다.

**Key interfaces:**
- `select_tags(tags, limit, allowed_ids, pinned_version)`와 `stale_pinned_lines(...)`: signature는 바꾸지 않는다.
- `TagRef.manifest_digest`: 전파의 기준이다.

**Acceptance criteria:**
- [ ] 이름이 Linux 태그처럼 보이지만 Windows 전용 태그와 digest가 같은 태그가 `select_tags` 결과에 없다.
- [ ] digest가 None인 Windows 전용 태그는 다른 태그를 제외시키지 않는다.
- [ ] `stale_pinned_lines`도 같은 태그를 제외한다.
- [ ] 기존 tagselect 테스트가 모두 통과한다.

**Out of scope:**
- 폴백 조건 변경(issue 02).
- `WINDOWS_ONLY` 정규식 자체의 범위 변경.

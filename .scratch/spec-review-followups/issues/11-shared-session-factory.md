## Agent Brief

**Category:** enhancement
**Summary:** API와 CLI에 중복된 "DB 구간마다 session을 여닫는 factory"를 core 한 곳으로 모은다.

**Current behavior:**
API app 생성 코드와 CLI가 같은 코드를 각각 따로 정의한다. engine으로 `sessionmaker(expire_on_commit=False)`를 만들고, `open_session()` context manager로 session을 열었다가 닫는 코드다. CLI 쪽 함수에는 반환 type 표기가 없다.

**Desired behavior:**
`whatfrom.core.db`의 공용 함수가 engine을 받아 `open_session` 팩토리(`Callable[[], ContextManager[Session]]`)를 돌려준다. API와 CLI가 둘 다 이 함수를 쓴다. 동작은 바뀌지 않는다. commit은 하지 않고 close만 하며, `expire_on_commit=False`를 유지한다.

**Key interfaces:**
- `whatfrom.core.db`의 새 함수: engine을 받아 session 팩토리를 돌려준다. 반환 type을 명시한다.
- `app.state.open_session`: 테스트가 rollback session으로 갈아 끼우는 seam이므로 그대로 유지한다.
- `recommend_for_question`이 받는 session 팩토리 계약.

**Acceptance criteria:**
- [ ] `sessionmaker`와 `open_session` 정의가 `core.db`에만 있다.
- [ ] API 테스트의 `app.state.open_session` 교체가 계속 동작한다.
- [ ] 계층 테스트를 포함한 전체 테스트와 `make lint`가 통과한다.

**Out of scope:**
- `session_scope`(commit하는 쪽) 변경.
- pool 설정과 timeout(issue 03).

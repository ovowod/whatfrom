# 03: 근거 인용과 인용 검증

**What to build:** 추천 이유가 주장 목록이 되고 주장마다 근거 인용(근거 번호와 글자 그대로의 문장)이 붙으며, 사용자는 인용마다 서버가 검증했는지와 실패 이유를 받는다. 검증에 실패해도 추천은 남는다. spec §두 번째 LLM 호출, §인용 검증.

**Blocked by:** 02

**Status:** ready-for-agent

- [ ] LLM 출력 schema가 이유 문단 대신 주장 목록을 두고, 주장마다 근거 인용 목록이 required로 있다. prompt는 주장 단위로 쓰고 근거 본문의 문장을 글자 그대로 인용하라고 지시한다.
- [ ] 인용 검증은 LLM과 DB를 쓰지 않는 결정론적 함수다. 없는 근거 번호, 빈 인용, 공백 정규화 뒤에도 본문에 없는 문장, 추천 이미지나 검증된 대안이 아닌 repository의 근거를 구분해 실패시킨다. 대소문자는 구분한다.
- [ ] 응답의 인용마다 검증 통과 여부와 실패 이유가 있다. 인용이 모두 실패해도 추천과 주장은 남고, 알림에 실패한 인용 수가 적힌다.
- [ ] 인용 검증은 추천 이미지와 대안의 실재성 검증 뒤에 돈다. 실재성 검증 규칙은 그대로다.
- [ ] 인용을 지어내거나 없는 번호를 인용하는 fake LLM으로 환각 테스트를 둔다. 조건 추출 실패 경로의 기존 API 테스트를 늘려 검증된 인용이 담기는지 본다. 인용 검증 함수는 테이블 주도 테스트로 모든 실패 이유를 다룬다.
- [ ] eval 결과 JSON에 문항마다 추천 이미지, 대안, 주장 목록과 인용별 검증 결과가 남는다. 부하 측정용 모의 LLM은 빈 인용 목록으로 답한다.
- [ ] README에 응답 예시와 인용 검증 규칙을 적는다.

# 02: 고정 참조와 번호 붙은 근거

**What to build:** 사용자는 응답 최상위에서 번호가 붙은 근거 목록을 받고, 후보마다 자기 근거의 번호와 `image@digest` 고정 참조를 받는다. 두 번째 LLM 호출도 같은 번호로 근거를 본다. spec §응답 계약, §두 번째 LLM 호출.

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] 근거마다 번호, repository, 섹션 제목, 본문, 출처 URL이 있다. 번호는 요청 안에서 1부터 매기고, (repository, 섹션 제목)으로 한 번만 담는다.
- [ ] 후보는 근거 본문 대신 근거 번호 목록을 담고, 그 번호는 근거 목록을 가리킨다.
- [ ] 후보마다 `repository:tag@digest` 고정 참조가 있고, digest가 없는 후보는 null이다.
- [ ] 두 번째 LLM 호출의 prompt가 응답과 같은 번호와 순서로 근거를 보여 준다.
- [ ] 저하 동작은 지금 코드 그대로다(조건 추출이 실패해도 벡터 검색으로 계속하고 두 번째 LLM을 부른다). LLM 실패, 추천 폐기, 조건 추출 실패 같은 저하 경로에서도 근거 목록이 담긴다. 임베딩 실패처럼 후보가 없으면 빈 목록이다.
- [ ] `/recommend` API 테스트로 위 동작을 고정한다.

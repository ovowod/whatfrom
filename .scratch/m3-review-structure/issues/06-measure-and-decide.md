# 06: M3 측정과 결정 반영

**What to build:** 두 안을 실제 LLM으로 같은 입력에서 재고, 측정 전에 적어 둔 기준으로 하나를 고른다. 결론으로 ADR 0003, 설계 문서, roadmap을 확정한다. 실제 API 비용이 들고, 인용 표본 검토는 사람이 한다.

spec: `.scratch/m3-review-structure/spec.md` (측정 절차, 고르는 기준, 결정 반영)

**Blocked by:** 01, 03, 04, 05

**Status:** ready-for-human

- [ ] 측정 전에 `eval/experiments/<날짜>-m3-review-structure/README.md`에 조건과 고르는 기준을 적고 커밋한다.
- [ ] 라벨 고정 입력, luna-none, V2 첫 측정과 같은 embedder로 두 안을 같은 날(KST)에 2회씩 돌린다. 회차마다 단일 선택부터 돌린다.
- [ ] 실제 API를 부르기 전에 사전 확인을 한다. 판정 칸이 가장 많은 문항으로 판정 단계를 한 번 불러, 응답의 `finish_reason`이 잘림이 아닌지 직접 본다.
- [ ] 네 실행 모두 40문항(요구 있는 20문항 포함)을 재고 건너뛴 문항이 0이다. 아니면 그 실행을 무효로 둔다.
- [ ] 측정하는 동안 수집과 색인을 돌리지 않는다. 네 실행의 문항별 후보 목록과 근거 목록(번호, repository, 섹션)을 비교해, 다른 문항이 있으면 그 회차를 무효로 두고 다시 잰다.
- [ ] 두 안의 1회차 결과에서 표본을 뽑는다. 조건은 판단 요구가 있는 문항, 문항당 최대 3개, 안당 50개, seed 0이다. 50개가 안 되면 같은 안의 2회차 결과를 묶어 채운다. 표본에서 인용이 진술에 맞게 붙었는지 검토하고 `score-citations`로 집계한다.
- [ ] 어느 한쪽의 채점 가능한 진술이 30개 미만이거나 채점 결과가 보류나 미측정이면, 인용 뒷받침률 조건을 만족하지 못한 것으로 본다.
- [ ] 결과 기록에 다음을 남긴다.
  - 묶음별 추천 정확도(2회 평균)와 검색 1위 대조군, 참고 정확도
  - 인용 뒷받침률, 인용 검증 통과율, 정규화 이유별 칸 수
  - 오답 적발률, 오판정률
  - 인용 길이 분포, 판정 단계의 출력 token, 묶음별 검토 단계 p95, 비용
- [ ] 고르는 기준대로 하나를 고르고 그 판정 과정을 적는다. 한계에 다음을 적는다.
  - luna-none 한 설정으로 쟀고, 이 결과는 모델 선택 근거가 아니다.
  - 판정 칸 진술은 고정 형식이라 이름을 가려도 형식으로 안을 알아볼 수 있다.
  - 20%p 기준은 독립 표본을 가정한 오차다. 한 문항에서 여러 진술을 뽑으므로 실제 오차는 더 클 수 있다.
- [ ] ADR 0003의 Status와 Consequences를 확정한다. 단일 선택을 고르면 설계 문서 §1, §2, §4, §5, §7, §8을 고친다. 판정 단계를 고르면 §7의 `Judgment`를 인용 목록으로 고치고, §7의 정규화 규칙 전체를 이 spec과 맞추고, 판단 요구가 없는 문항을 단일 선택으로 넘기는 혼합 구조를 적는다.
- [ ] roadmap의 M3 절에 결과를 적고 V3 절을 고른 안에 맞게 고친다. README 측정 결과에 M3를 더한다.
- [ ] 판정 단계가 탈락하면 결과 기록 뒤의 커밋에서 판정 단계 코드와 테스트, 검토 방식 option을 지운다. 지표 묶음과 표본 도구 option은 남긴다.

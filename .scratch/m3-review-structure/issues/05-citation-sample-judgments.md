# 05: 인용 검토 표본 도구가 판정 칸을 읽는다

**What to build:** `sample-citations`가 판정 단계 결과에서 판정 칸을 진술로 뽑는다. 두 안의 표본을 판단 요구가 있는 문항에서 같은 규칙으로 뽑을 수 있도록 option 세 개를 더한다. option을 주지 않으면 V2와 같은 표본이 나온다.

spec: `.scratch/m3-review-structure/spec.md` (인용 검토 표본 도구)

**Blocked by:** 02

**Status:** done

- [x] 판정 칸 중 `satisfied`·`violated`이고 검증을 통과한 인용이 있는 칸만 진술이 된다. `unknown` 칸과 버린 칸은 뽑지 않는다.
- [x] 진술 문장은 도구가 "<후보>가 요구 '<판단 요구>'를 만족한다/어긴다" 꼴로 만든다. 진술의 이미지는 그 후보다.
- [x] 한 칸의 검증된 인용 전체를 한 항목으로 본다. `verdict`와 `candidate_ok` 채점과 집계는 V2와 같다.
- [x] 후보 정보는 판정 단계의 prompt 기록에서 읽는다.
- [x] 문항당 상한 option이 있다. 기본값은 2다.
- [x] 판단 요구가 있는 문항만 쓰는 option이 있다. 기본값은 끔이다. 판단 요구는 결과 파일과 같은 golden set에서 읽는다.
- [x] 결과 파일 여러 개를 한 안으로 묶는 option이 있다. 앞 파일에서 먼저 뽑고, 50개가 안 되면 다음 파일에서 채운다. 문항당 상한은 묶은 안 전체에 적용한다. 기본값은 파일 하나가 한 안이다.
- [x] key 항목마다 원래 결과 파일과 진술 위치(주장 번호, 또는 후보와 판단 요구 번호)가 남는다. 묶은 두 파일에서 같은 문항, 같은 주장 번호가 나와도 항목을 가를 수 있다.
- [x] 안당 50개, seed, 안 이름 가리기, 합격선 90%는 바뀌지 않는다.
- [x] 단일 선택 결과와 판정 단계 결과를 한 번에 넣어 표본을 뽑을 수 있다.
- [x] CLI seam: fake provider로 만든 두 안의 결과 파일로 판정 칸 진술, 세 option, option 없이 뽑으면 기존 표본과 같음을 확인한다. `score-citations` 왕복도 판정 칸 항목으로 확인한다.

# 04: 집계와 고르기

**What to build:** 실험 폴더의 결과 JSON을 검증한 뒤 비교 표를 만들고, 공통 규칙으로 설정 하나를 고른다. 네트워크를 쓰지 않는다. spec §집계와 고르는 기준.

**Blocked by:** 02

**Status:** ready-for-agent

- [ ] 측정 도구와 같은 검증을 다시 하고, 어긋나는 파일이 있거나 회차 전후 snapshot이 다르면 표를 만들지 않는다.
- [ ] 설정별 추천 정확도(회차 평균), 태그 실재율, 출처 제공률, verify 거부, `seconds_advise` p50·p95, 재시도 문항 수, token, 40문항 비용을 보여 준다.
- [ ] 기준선보다 나빠진 보조 지표와 재시도가 섞인 설정을 표시한다.
- [ ] 5% 기준은 `kimi-max-r1`의 `seconds_total` p95를 바탕으로 판정하고, 참고 기준(추천 단계 p95 + `luna-low` 조건 추출 단계 p95)의 판정도 함께 보여 준다.
- [ ] 판정 결과를 `incomplete`, `needs_runs`, `inconclusive`, 선택 중 하나로 낸다. `needs_runs`면 하한 ±2문항이나 재시도 확인 때문에 다시 잴 설정을 알려 준다.
- [ ] 지연은 재시도 없는 회차만으로, 정확도는 모든 회차 평균으로 계산한다. 재시도 확인을 2번 해도 섞이면 지연 판정에서 뺀다.
- [ ] 고르는 결과가 결과 파일 순서와 무관하다는 테스트가 있다.
